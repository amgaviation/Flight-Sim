# Architecture

## Runtime targets

| Target | How |
|---|---|
| Dev server | `npm run dev` (Vite). METAR requests go through the Vite proxy `/proxy/awc`. |
| Browser build | `npm run build && npm run preview` |
| Windows exe | Electron 44 loads `dist/` through a privileged `app://` scheme (a secure context for Gamepad, Cache Storage and WebAudio). `electron-builder` produces an NSIS installer and a portable exe. CI runs it on `windows-latest` (`.github/workflows/build-windows.yml`). |

## Frame and step order

`core/SimLoop.ts` runs a fixed-timestep accumulator:

```
every animation frame:
  input.poll()                          -> input.* vars
  accumulate real dt * sim.rate
  while accumulator >= 1/120 s:
      if (step % 2 == 0) systems.update(1/60)   // scripted test pilot (idle unless started), then aircraft Subsystems in order
      fdm.step(1/120)                           // engines -> aero -> ground -> integrate -> publish fdm.*
      radios/fms.update at 20 Hz
  world.update(camera)                  // tile LOD, airport meshes
  cockpit controls update(dt)           // animate from vars
  displays.render (throttled per display refreshHz)
  exterior.update(dt); renderer.render(scene, camera)
  audio.update(dt)
```

Every stage is timed by `core/FrameProfiler` (`window.__sim.profile()`, docs/modules/qa.md).

## Coordinate frames

- **Physics**: the position is geodetic (lat, lon, alt MSL). Velocity is in local NED. Attitude is a body-to-NED quaternion. Each step integrates in local NED and then moves lat/lon using the WGS84 meridian and prime-vertical radii. Earth rotation is ignored, which is acceptable for flight training.
- **Rendering**: floating origin. The scene origin is a geodetic reference point, and the local ENU frame at that point maps to Three.js as x=east, y=up, z=south. The reference re-centres when the aircraft is more than 10 km away, and everything is re-positioned. Terrain vertices go geodetic → ECEF → ENU(ref), so the earth's curvature is exact.
- **Cockpit**: the cockpit group is a child of the aircraft object, and aircraft body axes map to Three.js. Helpers in `cockpit/geometry.ts` convert body metres (x fwd, y right, z down) to the Three.js local frame (x right, y up, z aft).

## Module contracts

- `SimVars` / `EventBus` (`src/core`): all shared state and commands.
- `FdmConfig` (`src/physics/types.ts`): aircraft aero, mass, engines and gear data. The FDM reads `surf.*`, `gear.*`, `eng*.inputs` and `fuel.*`, and writes `fdm.*`, engine outputs and `gear.wow*`.
- `WorldQuery` (`src/world/types.ts`): ground elevation, normal and surface type for gear contact, TAWS and radar altimeter.
- `NavDatabase` (`src/nav/types.ts`): airports, runways, ILS, navaids, fixes and airways.
- `CockpitControl` / `CockpitDisplay` / `CockpitBuild` (`src/cockpit/types.ts`): interactive 3D cockpit parts and canvas displays.
- `AircraftModule` (`src/aircraft/types.ts`): `meta`, `fdm` and `create(ctx)`. `create` returns the systems list, cockpit, exterior, state presets and checklists.

## Aircraft system pattern

Each aircraft composes blocks from `src/systems`:

```
ElectricalSystem (buses, batteries, generators, GPU, relays, CBs)
 -> FuelSystem (tanks, pumps, crossfeed, valves)       -> fuel.tank*_kg, eng*.fuel_on
 -> HydraulicSystem (EDP/ACMP/PTU, accumulators)       -> hyd pressures
 -> Pneumatic/Bleed + Pressurization + Ice protection
 -> FADEC / engine start logic                          -> eng*.n1_cmd_pct, starter, ignition
 -> FlightControls (mechanical or FBW) + Autopilot      -> surf.*
 -> Gear/Brakes/Steering (anti-skid)                    -> gear.*
 -> Sensors (ADC, AHRS, radio altimeter)                -> adc*.*, ahrs*.*
 -> Avionics logic (FMS, CAS/EICAS, TAWS, TCAS)
 -> Lighting (exterior, panel, flood; dimming buses)
```

Every subsystem is a `Subsystem { name; update(dt) }` and is updated in array order.

## Data

- `public/data/airports.json.gz`, `navaids.json.gz`, `fixes.json.gz`, `airways.json.gz`, `ils.json.gz` are generated by `scripts/build-navdata.mjs`.
- Terrain comes from AWS Terrain Tiles (terrarium PNG encoding, `https://s3.amazonaws.com/elevation-tiles-prod/terrarium/{z}/{x}/{y}.png`). It's fetched at runtime and cached (Cache Storage).
- Magnetic variation comes from the WMM2025 spherical harmonic model in `src/core/wmm.ts`.
